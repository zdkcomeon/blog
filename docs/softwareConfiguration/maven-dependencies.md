## 依赖加载优先级

这里记录 POM 依赖版本的加载优先级问题。

[maven中pom依赖相同jar包优先顺序加载版本_pom文件相同的以哪个为准-CSDN博客](https://blog.csdn.net/lizz861109/article/details/111594969)

存在三个概念：其实就是三个pom文件

1. 上级依赖：当前pom文件的父文件（业绩是）
2. 本级依赖：当前pom文件（也就是depends）
3. 下级依赖：当前pom文的所依赖的pom文件（也就是depends中的depends）
4. 潜规则：
    1. **本级的依赖****大于上下级依赖**
    2. **同一个级的依赖****，后加载的覆盖之前的依赖**
    3. **多个下级依赖，谁先加载就用谁的**
    4. **上级依赖是大于下级依赖的**

### 本级依赖 后加载的>先加载的

pom文件中，定义 依赖a的两个版本，分别是a1，a2

后加载的版本a2会把a1给覆盖掉。

### 下级依赖 先加载的>后加载的

当前pom文件两个依赖：a，b

a和b分别依赖了c的不同版本，这个时候项目加载的是c哪个版本的依赖,取决于当前a，b加载的顺序。

### 本级依赖 > 下级依赖

当前pom文件定义的依赖版本优先于下级依赖

### 本级依赖 > 上级依赖

当前pom文件定义的依赖版本优先于上级依赖

### 上级依赖 > 下级依赖

当前pom文件父依赖版本优先于下级依赖
