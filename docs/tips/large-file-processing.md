整理大文件下载、分段传输、流式传输和分批读写的处理思路。

## 如何下载一个大文件

分两种情况，一种服务端接口支持流式传输，分段传输，另外一种情况，不支持直接是一次性返回所有数据

### 服务接口直接一次性返回二进制数据

这种对于服务端接口直接返回一个大对象，客户端无法直接存储接受数据，只能调整服务返回的数据量或者调整客户端的内存，支持大文件下载传输，加载内存；其实服务端此时可以对文件进行压缩传输。但是这些操作的本质还是修改服务端的配置，客户端能做的就是调大内存，接受数据。

### 服务接口支持修改操作

 支持修改修改操作什么意思呢，就是允许对服务端接口修改操作，调整为我们想要的接口，比如改造下载接口（其实核心思想就是不一次传输全部对象，而是部分对象**，处理一点，返回一点，不要一下返回全部**）

1. 压缩文件发送
2. 分段传输文件，客户端一次下载一段文件，甚至可以多线程下载文件，因为分段了，只需要告知下载那段文件就可以，然后对这些文件合并
3. 流式传输文件，客户端从流中读取文件数据，一次读取一部分数据，而不是一次性读取所有数据，这时候就可以读取流中的数据，然后写入本地磁盘文件中，内存写入后释放掉
    1. [【Java流式下载大文件，避免OOM内存溢出】_java大文件下载-CSDN博客](https://blog.csdn.net/weixin_39825906/article/details/129355848)
    2. BufferedInputStream 缓存流的方式来获取下载文件，读取InputStream输入流时，每次读取的大小为5M，不一次性读取完，就可避免内存溢出的情况。前提是服务端返回的是一个流
    3. RestTemplate，使用RestTemplate流式处理下载大文件，需要先用RequestCallback定义请求头的接收类型application/octet-stream,然后restTemplate进行请求下载时，对响应进行流式处理而不是将其全部加载到内存中。

## 如何读取一个大文件到内存中

::: note
分析业务场景：

如果内存中必须存在一个完整的文件，但是这个文件超出了Jvm的内存限制，那么也是白搭的，没有办法，

除非是我们不需要这个文件全部，只能读取一点处理一点，释放掉一点，起始就是MapReduce思想，

分而治之。

:::

[Java IO——RandomAccessFile类详解-CSDN博客](https://blog.csdn.net/b15735105314/article/details/115677912)

流式传输

1、使用FileInputStream和BufferedInputStream（或RandomAccessFile）来从文件中读取数据（一次读取部分数据，比如读取一行，或者几行数据，读取的数据放入缓冲区）

2、使用OutputStream（如FileOutputStream或BufferedOutputStream）将数据写入到目标位置（同理一次写入一部分数据，写入的数据放入缓冲区，刷新数据到磁盘）

3、通过这种方式，可以一次只处理文件的一部分，而不是将整个文件加载到内存中
